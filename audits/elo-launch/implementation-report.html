ELO launch improvements

Wyndham Wombats VC · Implementation and verification report · 8 October 2026

Complete: 194 automated tests passed, 1,000 numerical parity cases passed, typecheck and frontend build passed. The running app was checked on a 390px mobile viewport. Nothing was deployed.

1. Numerical ELO remains unchanged

  • Starting ELO: 800. Four-stage K: 60 for matches 1–10, 40 for 11–30, 32 for 31–60, 20 for 61+.
  • The numerical calculator and K helper are AST-identical to their pre-change implementations. Expected wins still use live pre-result team averages, base-10 scale 400, existing rounding and a zero floor.
  • Private players still receive real updates. Public opt-in and established-player Top 5 rules remain intact.
  • No attendance points, seasonal inflation, rating reset, guaranteed promotion or competing ranking system was introduced. Matchmaking and balancing source were not changed.

2. Approved display thresholds

The audit's single recommended mapping was explained before implementation. New players display as Iron 1 at 800, or Iron on the public leaderboard. Threshold changes affect labels, not numeric ratings. Except for the retained lower Iron bounds, divisions are 50 points and tiers span 150 points. These are skill labels, not population quotas or promised progression timelines.

3. Match-count consistency and approved repair

The original counter migration started older players at zero without backfilling prior completed appearances. All 14 stored counters matched modern completed appearances exactly, but omitted 105 older appearances.

Completed roster snapshots now provide one authoritative appearance count: each player counts once per distinct completed match. K progression, provisional status and leaderboard eligibility use that history. Result writes and reversals check the cached counter rather than silently repairing it. Completion, reopen, correction and duplicate protection remain transactional.

The explicitly approved repair updated 14 workspace counters: total 176 → 281. It changed no numeric ELO, original audit rows, match snapshots, priority state or accounts. Verification after restarting the app also matched the private backup, excluding only the approved counters. Existing table root pages were preserved.

Private backup: artifacts/api-server/data/backups/before-counter-repair-20261008T114959212489Z.sqlite3. Backups are ignored by Git and are not served as public assets.

The repair is explicit and idempotent; it never runs automatically on application startup. For a separate database with legacy counters, its repair must be explicitly approved and run against that database. No production database was accessed or modified.

4. Admin adjustments and reversal integrity

The additive elo_adjustments ledger records actual before/after ELO, delta, administrator, retry identity and its position relative to result history. The additive progression_repairs ledger records approved counter repairs. The original audit table was not rebuilt.

Reversal removes the recorded match contribution while preserving subsequent recorded adjustment amounts. Example: 800 → match win 830 → admin sets 900 (+70) → reverse win 870. Adjustments are not counted as games or reapplied on request retries. Name/preference edits omit an unchanged rating to avoid overwriting concurrent results.

The existing later-result guard remains. Historical K values are never recalculated. Repaired historical results reverse to the remaining authoritative appearance count, leaving their original, potentially incomplete audit metadata unchanged. Corrections then use the correct current stage for their newly applied result.

Admins can inspect adjustment and repair history in the existing player edit dialog or GET /api/admin/players/{playerId}/rating-audit. Anonymous requests return 401; signed-in non-admins return 403. Existing result/reversal audit access and privacy gates are preserved.

Intentional safeguards: Unknown unaudited legacy rating changes block ambiguous reversals for review. A reversal that would become negative after retaining manual adjustments also blocks atomically; it does not silently discard an adjustment or clamp away the conflict. No historical adjustment records were invented.
