# Current problem

Currently, after the admin enters the final score and completes/submits a match, the app automatically navigates to:

**Match History**

I do not want this automatic navigation.

When running volleyball socials, I want to complete a match and remain on the **Current Match** page.

# Desired behavior

When the admin enters the final score and successfully completes/submits the match:

1. Save the result using the existing backend/API logic.
2. Run the existing ELO update logic exactly as it currently works.
3. Update Match History normally.
4. Mark the match as completed using the existing logic.
5. Show a success popup/modal.
6. Keep the admin on **Current Match**.

Do NOT automatically navigate to Match History.

# Success popup

After the backend confirms the match has been completed successfully, show a simple confirmation popup/modal:

**Match Complete**

Message:

**The match result has been saved successfully.**

Button:

**OK**

The exact styling should follow the app's existing popup/modal design.

Do not redesign the UI just for this popup.

# After clicking OK

When the admin closes the Match Complete popup:

Remain on:

**Current Match**

Do NOT automatically navigate to:
- Match History
- Create Match
- Leaderboard
- Any other page

# Current Match should refresh correctly

After the completed match is saved, refresh/update Current Match using the existing application state/API.

If there is another active/current match waiting to be played, Current Match should display the appropriate next active match according to the app's existing current-match logic.

If there are no remaining active/current matches, show the existing appropriate empty state.

Do not invent a new match queue system if one does not already exist.

The important behavior is:

**Complete Match → confirmation → remain on Current Match → show the correct current state**

rather than:

**Complete Match → automatically navigate to Match History**

# Do not change the completion logic

The existing result-processing logic should remain the source of truth.

Completing a match should still correctly:

- Store the final score.
- Determine the winner.
- Mark the match as completed.
- Apply the existing ELO changes.
- Store/update ELO history as currently implemented.
- Make the completed match available in Match History.
- Update any existing leaderboard/player data that normally changes after match completion.

This task should NOT alter those calculations.

It is primarily a navigation/state-refresh UX change.

# Failure behavior

Only show **Match Complete** after the backend confirms that the match result was successfully saved.

If completion fails:

- Do NOT show the success popup.
- Do NOT navigate away.
- Do NOT incorrectly mark the UI as completed.
- Keep the entered score where practical so the admin can retry.
- Use the existing error handling/message.

Most importantly, do not run the completion operation twice.

# Prevent duplicate submission

Please make sure the completion action cannot accidentally be submitted multiple times while the first request is processing.

If the existing button already has loading/disabled behavior, preserve it.

Otherwise, disable the completion/save-result action while the request is in progress.

This is important because completing the same match twice must not apply ELO changes twice.

Do not redesign the button; just preserve/add appropriate submission protection if necessary.
