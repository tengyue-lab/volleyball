## Part 4 — Fix No Roles Lock

Manual Selection → No Roles Lock must behave like every other normal rated match, except it has no assigned player positions.

### Match creation

- Allow valid 12-, 13- and 14-player rosters.
- Save Team A and Team B.
- Save match date and normal match metadata.
- Store `manual_mode = no_roles_lock`.
- Leave player positions and preference ranks unassigned.
- Do not invoke Fill or role-assignment logic.
- Do not show a successful save message until the backend confirms persistence.

### Match completion

When an admin records a result:

- Save the score and winner.
- Mark the match completed.
- Show it in Match History.
- Allocate ELO to every participating player.
- Update completed-match counters and K-factor progression.
- Create the normal ELO-history and rating-audit records.
- Support result corrections and reversals.
- Prevent duplicate ELO awards.
- Use the same authoritative ELO calculation as Auto Balance and Roles Lock.

Ensure completion, ELO changes and required audit writes are transactionally consistent.

### Position-rotation fairness

**No Roles Lock must never change future position priorities.**

- Do not generate position-assignment or priority-compensation events.
- Do not invent positions or preference ranks.
- Do not count No Roles Lock appearances in the last-three-eligible-role-assigned-match window.
- Do not reset or dilute existing rotation history.
- Preserve the existing position-rotation fairness algorithm.

No Roles Lock matches must still count normally for ELO and completed-match progression.
