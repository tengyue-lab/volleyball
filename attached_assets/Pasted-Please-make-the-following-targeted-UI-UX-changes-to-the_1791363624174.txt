## 1. Remove the redundant "Next Game" button

On the first step of Create Match, where the user selects the match date, there are currently two actions that effectively do the same thing:

- "Next Game"
- "Continue to players"

Remove the **"Next Game"** button.

Keep **"Continue to players"** as the single action for progressing to player selection.

Make sure removing "Next Game" does not remove or break any required state-setting or date-selection logic.

## 2. Split Player Selection and Team Selection into separate steps

Currently, after selecting approximately 12–14 players, the Create Match page expands downward and shows the Team A / Team B selection interface on the same long page.

Change this so Create Match behaves like a multi-step flow.

The flow should be:

**Step 1 — Date**

Select the match date.

Button:
**Continue to players**

↓

**Step 2 — Players**

Select the players participating in the match.

Keep the existing player selection functionality.

Once enough players have been selected, provide the existing appropriate action to continue/generate teams.

↓

**Step 3 — Teams**

Display the Team A / Team B selection and balancing interface here.

The Teams section should NOT simply appear underneath the player-selection interface and make the page very long.

It should behave like another mini-step/tab within Create Match.

The goal is to keep the Create Match interface compact and easy to navigate.

Preserve the selected players when moving between the Players and Teams steps.

If the user navigates back from Teams to Players, their existing player selections should still be there.

Do not unnecessarily recreate or duplicate match-session state. Reuse the existing session/state architecture where possible.

---
